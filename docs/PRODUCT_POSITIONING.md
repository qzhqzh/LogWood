# 空心树洞产品定位

> 状态：Accepted / 产品定位 SSOT
> 最近修订：2026-08-23
> 实现约束同步见 [`../PRODUCT.md`](../PRODUCT.md)

## 一句话定位

**空心树洞是一个把提示词正文、真实效果、来源、AI 归属和验证记录放在一起的增强版提示词仓库。**

它不试图成为另一个 AI 导航站。它帮助作者把散落在聊天、链接、截图和实验中的提示词变成可执行、可比较、可追溯的长期资产。

品牌副标题：**可验证的提示词仓库**。

## 为什么存在

普通提示词收藏常见四个断点：

1. 只有一句正文，不知道真实效果；
2. 只有漂亮效果，不知道对应指令；
3. 同类提示词分散，无法在同一上下文比较；
4. 来源、模型、版本和人的修改没有记录，结论难以复核。

空心树洞把这四部分重新连起来。成功不是收录更多，而是让每条公开提示词更容易被执行、比较、验证和继续改进。

## 产品主对象

### Prompt / Skill

当前数据库以 `Skill` 承载主提示词对象。它至少包含：

- 标题、分类、摘要与可执行正文；
- 可选的真实效果图与说明；
- 可选外部来源；
- Tags；
- draft / published / archived 状态；
- 可选且完整的 AI provider/model/version/generatedAt；
- Review、Evaluation、Candidate 来源与 Article 引用。

`Target.prompt` 是历史提示资源，保留原 ID、slug、链接与互动，只在兼容区展示。新提示词不再写入 Target。

### Supporting Records

- `Candidate`：尚未成熟的灵感、链接、截图和原始材料；
- `Evaluation`：版本、环境、任务、输入输出、证据、限制和结论；
- `Review`：低门槛的使用反馈、问题和阶段性判断；
- `Article`：实验、比较、复盘和长期解释；
- `App` / `VisualAsset`：项目结果与有来源、hash、权利状态的视觉资产。

## 核心链路

```text
收集箱 Candidate
  → 人 / AI 整理
  → Prompt Skill 草稿
  → 效果 + 来源 + 归属
  → 人工发布门禁
  → 提示库
  → 验证 / 反馈 / 笔记
```

AI 只能整理和建议，不能批准或发布。任何 AI 草稿都必须保留模型归属；新 Skill 和 Candidate 晋升结果默认是 draft。

## 公开信息架构

| 入口 | 用户问题 | 路由 |
|---|---|---|
| 提示库 | 有哪些可以直接执行的提示词？ | `/skills` |
| 提示词对比 | 同类指令、效果和证据有何不同？ | `/compare/prompts` |
| Awesome | 哪些开源方向真正值得投入，下一项最小工作是什么？ | `/awesome` |
| 验证记录 | 哪些效果在什么环境下被验证？ | `/evaluations` |
| 笔记 | 作者如何解释实验与长期判断？ | `/articles` |
| 关于 | 这套系统为何由秦建立？ | `/about` |

Awesome 不是热度导航站：候选必须包含官方上游、许可说明、本站能力连接和最小可交付；1–5 分只衡量投入意愿，不替代正式验证。作者工作流放在二级入口：收集箱 `/candidates`、AI 整理 `/forge`、归档 `/scraps`。旧 `/tools`、`/app`、`/compare` 继续可访问，但不占据新的一级导航。

## 关键体验

### 1. 效果在正中间

桌面首页使用三栏工作台：提示索引 / 效果舞台 / 证据 Inspector。真实 `effectImageUrl` 在中心以 `object-contain` 显示；无效果图时展示正文回退，明确标记待补充。

### 2. 同类并排比较

提示库允许选择 2–3 条。对比页按同一行展示：

- 实际效果；
- 完整提示词；
- 说明与分类；
- 正式验证和使用反馈计数；
- 来源和最近更新时间；
- AI 归属。

系统不制造“综合最优”分数，让人基于任务和证据判断。

### 3. 公开内容可检查

Prompt detail 保持三部分同时可见：正文、效果、Inspector。Evaluation 与 Review 在下方继续生长；由 Candidate 晋升的对象保留原始历史。

### 4. 工作台按能力运行

`/workbench` 不再把所有 Prompt 都交给文本模型。文本类使用 DeepSeek，图像类自动选择 CPA 生图模型；本次输出居中预览并显示 provider/model 归属，但不会写回 Prompt、Candidate、Article 或发布状态。若对应能力未配置，运行入口保持禁用并明确显示缺失能力。

## 视觉与语气

Prompt surface 采用 ASCII character field：

- 近黑背景与高对比磷光绿；
- 字符边框和硬分隔；
- 等宽操作字体；
- 0–2px 角、无阴影、无玻璃和无渐变发光；
- hover 主要使用反相，而不是浮起卡片；
- 装饰字符固定、无语义且 `aria-hidden`；
- 真实图片始终比装饰 ASCII 更重要。

作者页保留暖纸、墨色与克制诗性，但仍共享导航、来源检查和人的发布责任。

品牌人格：直接、诚实、有判断力。核心句仍是：**“信号太多，意义太少。”**

## 与来源项目的关系

- `LogWood` 是唯一运行和发布根；
- `personal_site` 提供作者叙事与 Now/Projects/Values/Notes/Links/Contact 内容，不提供运行技术栈；
- `personal_site_x` 的有价值内容和结构吸收后，不再作为运行依赖；
- `design-preview` 的非重复概念稿只能经过 VisualAsset 来源/hash/权利审查进入系统，不能直接复制到 `public`；
- 来源仓库是否归档是独立决策，本次不删除。

## 不做什么

- 不按热度堆砌 Prompt；
- 不伪造效果图、测试数、模型版本或来源；
- 不把旧工具、App 和视觉概念稿假装成 Prompt；
- 不允许 AI 直接发布；
- 不为了统一而删除历史 URL 或数据；
- 不引入 Astro、Three.js、R3F、Motion、Lenis 或第二套主题运行时；
- 不使用已废弃的 Register 叙事或入口。

## 衡量标准

1. 首页首屏能选择真实提示并看到居中效果；
2. 两到三条同类提示词可通过独立 URL 对比；
3. 草稿不会出现在公开提示库；
4. AI attribution、来源、验证和反馈都能被检查；
5. 历史数据、路由、上传文件和交互记录不丢失；
6. 桌面/移动真实渲染、自动化测试、生产构建和数据恢复演练通过。
